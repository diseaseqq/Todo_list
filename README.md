# Список задач

Небольшое браузерное приложение для планирования задач. Клиент написан на HTML, CSS и JavaScript без сборщика и внешних зависимостей; данные хранятся на PHP/SQLite backend.

## Запуск

Для работы требуется PHP 8.3 с PDO_SQLite и mbstring. Из корня проекта запустите локальный сервер:

```powershell
$env:TODO_ENV = 'development'
php -S 127.0.0.1:8080 -t public public/index.php
```

Откройте `http://127.0.0.1:8080`. Для локального входа сначала создайте аккаунт администратора по инструкции ниже.

## Возможности

- Создание и редактирование задач с описанием, сроком, приоритетом и категорией.
- Подзадачи и повторение задач.
- Поиск по названию и описанию, фильтрация и сортировка.
- Статистика активных, выполненных и просроченных задач.
- Архив с восстановлением и окончательным удалением.
- Светлая и тёмная темы.

Задачи, категории и настройки аккаунта загружаются с сервера и доступны после входа с разных устройств. В `localStorage` хранится только выбранная тема. Данные старой версии автоматически не импортируются.

## Backend (в разработке)

Backend использует PHP 8.3 и PDO_SQLite без внешнего фреймворка. Реализованы версионированные миграции, CLI-команды обслуживания базы, создание первого администратора и JSON API аккаунтов, задач, повторов, подзадач, категорий, статистики и архива. Интерфейс подключён к серверной авторизации и API; администратор входит через ту же простую форму, что и обычный аккаунт.

В production Nginx должен использовать `public` как web-root и передавать запросы приложения в PHP-FPM; entry point обслуживает только разрешённые файлы интерфейса и API. В окружении разработки задайте `TODO_ENV=development`; путь БД по умолчанию — `storage/app.sqlite`. Production обязан явно передать абсолютный `TODO_DB_PATH` вне каталога `public`, иначе конфигурация завершается ошибкой. Файл `.env.example` служит памяткой переменных окружения и автоматически не загружается.

Production-сессии требуют HTTPS. Пока Nginx/TLS на VPS не настроены, вход через публичный HTTP по IP не будет работать; не переводите production-сессию на небезопасный HTTP.

Пошаговые инструкции по созданию первого аккаунта на Windows и на VPS приведены в [инструкции первого администратора](FIRST_ADMIN_SETUP.md). Команда интерактивно запросит email и пароль; стандартного пароля нет. Она создаёт также шесть стандартных категорий для этого аккаунта. Повторный запуск миграций безопасен, а повторное создание администратора отклоняется. Подготовка Nginx, HTTPS-сертификата для IP и его автообновления описана в [инструкции развёртывания на VPS](VPS_DEPLOYMENT.md).

Начальные маршруты аккаунта: `GET /api/auth/csrf`, `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout` и `GET /api/auth/me`. Описание маршрутов, полей и ответов — в [контракте API](backend/API.md). Для изменяющих запросов получите CSRF-токен и отправьте его в заголовке `X-CSRF-Token`; при изменении задачи или категории передавайте текущую `version`.

На целевом сервере используется PHP-FPM за Nginx. Каталог БД и резервные копии должны находиться вне публичного web-root; ежедневное копирование и восстановление SQLite описаны в [инструкции по резервным копиям](BACKUP_AND_RESTORE.md), а реальные пути и права — в [плане backend](BACKEND_SQLITE_IMPLEMENTATION_PLAN.md).
